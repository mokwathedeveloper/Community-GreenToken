## Overview

GreenToken (GTK) is a utility token minted exclusively for verified real-world eco-actions. Unlike speculative tokens, GTK's supply is directly tied to quantifiable human behaviour: every token in circulation represents a completed, admin-verified environmental action.

The token is deflationary by design — redemptions permanently destroy GTK — creating natural scarcity as community activity grows.

## Mint-on-Verify Flow

GTK is created **only** through the following verified path:

```
1. Member submits eco-action + photo evidence
         ↓
2. Server computes SHA-256(photo) → evidence_hash
         ↓
3. ActionRegistry.register_action(submitter, evidence_hash, action_type)
         ↓
4. Action stored on-chain with status: PENDING
         ↓
5. Org admin reviews evidence in /org/admin/actions
         ↓
6. Admin approves → ActionRegistry.verify_action(action_id)
         ↓ [cross-contract call, atomic]
7. GreenToken.mint(submitter_address, reward_amount)
         ↓
8. GTK appears in user wallet on Stellar
```

**No other minting path exists.** The smart contract enforces this — the admin keypair is the only authorized minter, and it only signs transactions generated by the verify flow.

## Deflationary Burn Mechanics

Every token redemption calls `GreenToken.burn()` atomically:

```
Member selects reward (e.g., "Free Coffee — 50 GTK")
         ↓
Member signs redemption transaction with Freighter wallet
         ↓
RewardManager.redeem(user_address, reward_id)
         ↓ [cross-contract call, atomic]
GreenToken.burn(user_address, 50_GTK)
         ↓
Reward fulfilled · GTK permanently destroyed
```

**Net supply dynamics:**
- Every verified action → GTK minted (supply up)
- Every reward redeemed → GTK burned (supply down)
- Community activity increases both simultaneously
- Long-run: active redemption communities have higher scarcity
- Passive holders benefit as active communities shrink supply

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| **Admin key compromise** | Admin key rotation capability; multi-sig planned for Phase 4 |
| **Fake action fraud** | Photo evidence required; admin human review; SHA-256 replay prevention |
| **Org churn reducing demand** | Treasury allocation funds incentives for new org acquisition |
| **Freighter wallet risk** | Platform-side balance tracking; GTK not lost if wallet inaccessible |
| **Smart contract bug** | Internal review complete; external audit planned before Mainnet |
| **Regulatory risk** | GTK is a utility token (redeemable for specific goods), not a security |
