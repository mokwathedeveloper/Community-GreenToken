# Community GreenToken Accessibility Checklist

This document provides a **professional accessibility checklist** for the Community GreenToken web application, ensuring compliance with WCAG 2.1, keyboard navigation, color contrast, readability, and screen reader support.

---

## 1. WCAG 2.1 Compliance
- Ensure all pages meet **WCAG 2.1 AA standards**.
- Provide **text alternatives** for all non-text content.
- Ensure content is **operable, perceivable, and understandable**.
- Include accessible **forms, error messages, and notifications**.

## 2. Keyboard Navigation and Focus Management
- All interactive elements should be reachable using **Tab key**.
- Provide visible **focus indicators** on active elements.
- Ensure proper **focus order** that matches visual layout.
- Include skip links for faster navigation to main content.

## 3. Color Contrast and Readability
- Text and interactive elements must have **sufficient contrast** (minimum 4.5:1 for normal text).
- Avoid using color as the **only means to convey information**.
- Ensure **font sizes, line spacing, and weight** are readable on all devices.
- Test contrast ratios with tools such as **Contrast Checker** or **axe**.

## 4. Screen Reader Support and ARIA Roles
- Use **semantic HTML5 elements** for all content.
- Add **ARIA roles, labels, and properties** to custom components.
- Ensure dynamic content updates (like dashboards or toast notifications) are **announced to screen readers**.
- Test with screen readers (e.g., NVDA, VoiceOver) for usability.

## 5. Additional Best Practices
- Ensure **interactive charts and dashboards** have alternative text descriptions.
- Provide **keyboard shortcuts** for frequently used actions.
- Validate **contrast and readability** for light and dark modes.
- Include **accessible error messages** and guidance for form corrections.

This checklist ensures Community GreenToken is **inclusive, compliant, and usable by all users**, providing an accessible experience consistent with professional UX/UI standards.
